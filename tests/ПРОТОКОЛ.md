# Протокол проверки версии 1.0

Дата: 21 октября 2026 года. Браузер: Chromium 151.0.7922.34. Проверки выполнены локально с программным WebGL-рендерингом.

## Выполнено

- 14 автоматических проверок, все PASS. Проверены движение, прыжок и приземление, пауза, заблокированный выход, рывок через преграду, контрольная точка и сохранение целей после падения, восстановление после перезагрузки, переключатели, урон, финал и повторная игра. Перечень и исходные результаты — в results.json. Для проверок отдельных состояний использовалось тестовое позиционирование персонажа.
- Отдельный сценарий keyboard-route.cjs прошел все три уровня только клавиатурными событиями: движение, прыжки, рывки и E. Персонаж не перемещался программно, уровни не пропускались, состояние не изменялось. Результат — keyboard-route.json. Видео фактического выполнения — screenshots/keyboard-playthrough.webm (относительно корня проекта). Это автоматическое прохождение, не испытание с пользователями.
- Запуск index.html через file:// с отключенной сетью: начало игры, отображение уровня и отсутствие JavaScript-исключений. Результат — offline-launch.json.
- Снимки меню, трех уровней и финала получены из работающего приложения. Проверена перестройка интерфейса при размере окна 390×844; работа на физическом телефоне не проверялась.

## Не подтверждено

- Целевые 60 кадров/с на компьютере студента, совместимость со всеми браузерами и физическими телефонами.
- Удобство навигации и баланс по результатам независимых игроков.
- Совместимость с персонажем прошлых семестров: вместо него разработан новый геометрический Носорог.
- Сроки и трудозатраты студента, утверждение руководителем, размещение в публичном репозитории.

## Повторение проверок

Для тестов отдельно нужны Node.js и Playwright: установите playwright и Chromium в собственном окружении. Запустите локальный сервер в корне проекта на порту 8765; затем node tests/automated-checks.cjs и node tests/keyboard-route.cjs. Для обычной игры эти инструменты не нужны. Адрес с #test включает диагностический интерфейс; он используется сценариями для чтения состояния, а в проверках отдельных компонентов — также для подготовки состояний.
